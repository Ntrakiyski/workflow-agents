description: Build, qualify and recover the pinned Pi OfficeCLI document workload without coupling it to reusable infrastructure.
---

1. Read package `AGENTS.md`, README and verification evidence. Confirm the currently authorized minimal UI scope.
2. Verify supplied source assets exist; review them before reuse. Preserve originals and record source checksums. Missing helpers remain missing until independently implemented and tested.
3. Keep runtime dependencies pinned to immutable checksums plus npm integrity lock. Use Docker to extract checksum-locked ICU and copyright only from the immutable source image in `runtime-lock.json`; never copy host libraries or enable invariant globalization. Build with `python3 build_runtime.py`; retain the generated bundle metadata and SHA256 outside Git's binary history.
4. Run `npm test` for archive/path/checksum/OOXML/tool boundary negatives. Extract the bundle using `bootstrap.install` and run `python3 tests/runtime-smoke.py --runtime <path>` for actual Node, Pi, OfficeCLI, persisted Unicode editing and bundled guest validation. Run this smoke inside the exact approved immutable slim image with no network and read-only runtime/source mounts; host-only success is insufficient.
5. Render a nonsecret profile using `render_profile.py`. Supply only an approved OCI digest, exact LiteLLM endpoint/model and the generated archive metadata. Bind the Provider secret reference to a runtime-only key. Do not write a literal key into profile JSON.
6. Confirm the effective network policy has inbound disabled and the approved outbound hostname and an HTTPS endpoint configured on port 443. Cloud uses hostname-only matching; do not claim port enforcement from that rule. Run real permitted/denied traffic probes separately; metadata is not complete isolation proof.
7. Stage runtime and request files only through the versioned scoped transfer API. Submit the approved workload through Runner using a stable request UUID and owner-scoped idempotency. Never replay a fenced uncertain execution under a new reference.
8. Verify the stdout manifest pointer against the transferred result bytes. Validate a real guest-produced result against the strict application manifest schema, including `session_files[].media_type: application/x-ndjson`; mocks must retain that exact field. Independently validate checksums, OOXML package boundaries and final request identity in the controller. Treat rendered layout/content accuracy as unverified unless independently tested.
9. Export all required artifacts and session JSONL files into application-owned object storage, record durable audit evidence, then stop the same environment through the authenticated API. Stop is not destroy.
10. If a completed job cannot export, preserve all execution identities and the guest fence. Use only the reviewed audited same-job export-only recovery procedure; never dispatch or replay the model to fix a controller contract mismatch. Keep recovered and uninterrupted journey evidence distinct.
11. Record actual service commits, runtime SHA, request/job/sandbox/run IDs, original/output/checkpoint checksums, durable export and same-box stop, and browser authorization evidence. A bounded hosted qualification must link its actual evidence and state its scope; it does not change stable-release or broader infrastructure acceptance. For shared-runtime rc3, additionally run `tests/shared-runtime-smoke.py` against the extracted read-only runtime in the exact slim image. Qualify tracked preparation before concurrent requests, independent cancellation and idle stopping through real services separately. The historical rc2 uninterrupted synthetic DOCX journey is recorded in package `VERIFICATION.md` and `release.json`.
